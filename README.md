# Личный Telegram-ассистент с Outlook

Для продолжения разработки с другого компьютера см. [CONTINUE.md](CONTINUE.md)
и [журнал работы за 17.10.2026](docs/worklog/2026-10-17.md).

Python 3.11+ (проверено на Python 3.13, macOS Ventura Intel). Long polling, ChatGPT plan usage через официальный OpenAI SDK и streaming Responses API с function calling, Microsoft Graph v1.0 delegated OAuth device flow, SQLite. Пишет по-русски; часовой пояс Europe/Minsk. Все изменения и удаления требуют кнопки подтверждения, действующей 10 минут. Создания выполняются сразу по вашему запросу.

## 1. Установка

Откройте Terminal:

```bash
cd /path/to/telegram-assistant
./setup.command
```

Для воспроизводимой установки на сервере вместо requirements.txt используйте requirements.lock.txt после создания venv. Никогда не переносите саму .venv между компьютерами.

## 2. Telegram

1. В Telegram откройте официального @BotFather: https://t.me/BotFather.
2. Отправьте `/newbot`, задайте имя и уникальное имя, заканчивающееся на `bot`.
3. Токен сохраните локально в `.env` как `TELEGRAM_BOT_TOKEN`. Не публикуйте его и не отправляйте в чат.
4. Узнайте свой числовой Telegram user ID. Можно переслать своё сообщение боту @userinfobot (сторонний сервис), либо получить ID самостоятельно через официальный Bot API `getUpdates` после сообщения вашему боту. Документация: https://core.telegram.org/bots/api#getupdates. Не вставляйте токен в публичные URL или скриншоты.
5. Запишите число в `TELEGRAM_USER_ID`. Бот принимает сообщения только от этого ID в личном чате, группы игнорирует.

## 3. Подписка ChatGPT — без API-ключа

Используется официальный Sign in with ChatGPT для личного локального проекта. Нужен подходящий аккаунт Plus или Pro с разрешением ChatGPT plan usage. Доступ конкретного аккаунта проверяется при входе и успешном ответе модели. Бот не использует OPENAI_API_KEY и не переключается на платный API.

1. Остановите бот перед авторизацией, чтобы процессы не обновляли один сеанс одновременно.
2. Запустите `./chatgpt-login.command` (можно двойным щелчком).
3. Скопируйте показанную ссылку в браузер на этом же Mac.
4. Войдите в ChatGPT и разрешите приложению Telegram Personal Assistant использовать ваш план. Пароль вводится только на сайте OpenAI.
5. Дождитесь сообщения «Подписка ChatGPT подключена» в Terminal.

Модели загружаются из каталога вашей подписки. Пустой `CHATGPT_MODEL=` автоматически выбирает первую видимую модель. Чтобы выбрать другую, укажите её доступный slug. Ответ учитывается только после завершения streaming Responses API. История из обычного ChatGPT не импортируется.

OAuth-сеанс и идентификатор установки хранятся в `data/chatgpt-session.json` и `data/chatgpt-host.json`. Токены — секреты, не отправляйте их в чат. Сеанс обновляется автоматически. Встроенные cookies и чужие сеансы Codex не используются.

Управление лимитами: https://chatgpt.com/#settings/Usage или `/usage` в Telegram. Использование расходует лимиты подписки и зависит от настроек аккаунта. Для требования «только оплаченная подписка» не покупайте дополнительные кредиты и не включайте автоматическое пополнение в аккаунте. При недоступности подписки или лимите бот прекращает запрос, платного резервного режима нет.

Официальные источники:
- https://developers.openai.com/siwc/token-sharing-open-source/sign-in
- https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference
- https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions

## Gmail и заметки iPhone

В Google Cloud создайте проект и включите Gmail API. В Google Auth Platform
настройте Branding (название и контактный email), Audience — External,
для первого теста добавьте свой Google-аккаунт в Test users. В Data Access
добавьте `https://www.googleapis.com/auth/gmail.modify`. Создайте OAuth client
типа Desktop app, скачайте JSON и сохраните приватно в `data/google-client.json`.
Это отдельная авторизация от Google, подключённого на iPhone или в ChatGPT.

Запустите `./google-login.command` на Mac и откройте напечатанную ссылку
в браузере того же компьютера. Используется локальный callback 127.0.0.1,
случайный порт, PKCE и тайм-аут 10 минут. Не присылайте callback URL или JSON
в чат. Refresh token сохраняется атомарно в `data/gmail-token.json` с правами
600. При необходимости передайте файл на VPS по SSH в каталог DATA_DIR,
назначив владельца пользователя службы и права 600. Постоянный клиент
`GoogleAuth.token()` обновляет истёкший доступ. Одновременно обновлять один
файл должен только один процесс.

В Testing согласие и refresh token истекают через 7 дней. Для постоянного
личного использования настройте Production перед финальной авторизацией;
personal-use приложения могут подпадать под исключение из проверки Google.
Production не означает гарантированно бессрочный доступ.

При наличии `data/gmail-token.json` на старте бот включает создание заметок.
Напишите или скажите «Создай заметку Идеи: съездить в Брест». Запись появляется
в разделе Gmail / Notes приложения «Заметки» iPhone, если Google подключён
там с включённой синхронизацией заметок. Проверка на iPhone владельца прошла.
Создание выполняется сразу; текст и переносы строк сохраняются, HTML экранируется.
При неопределённом результате проверьте Notes перед повтором. Поиск и чтение заметок доступны; изменение и удаление заметок пока не реализованы.

Для диагностики без изменения писем: `.venv/bin/python -m assistant.gmail_check`.
Опция `--create-test-note` добавляет одну тестовую запись; локальный маркер
предотвращает повторную отправку при повторном запуске. `gmail.modify` допускает
реализованные почтовые операции; немедленное безвозвратное удаление не требуется.

Источники: [Google Desktop OAuth](https://developers.google.com/identity/protocols/oauth2/native-app),
[Audience](https://support.google.com/cloud/answer/15549945),
[исключения для personal use](https://support.google.com/cloud/answer/13464323).

## 4. Microsoft Outlook OAuth

Нужна учётная запись Microsoft с календарём Outlook/Exchange Online.

1. Откройте https://entra.microsoft.com/ → Identity → Applications → App registrations → New registration.
2. Название: `Telegram Personal Assistant`.
3. Для обычного Outlook.com и рабочих аккаунтов выберите Accounts in any organizational directory and personal Microsoft accounts. Redirect URI для device flow не требуется.
4. Скопируйте Application (client) ID в `MICROSOFT_CLIENT_ID` в `.env`.
5. Authentication → Advanced settings → Allow public client flows → Yes → Save.
6. API permissions → Add a permission → Microsoft Graph → Delegated permissions → `Calendars.ReadWrite`. Application permissions не нужны. В организации администратор может потребовать consent. MSAL автоматически запрашивает служебные OAuth scopes для обновления токена.
7. `MICROSOFT_TENANT_ID=common` подходит для смешанного типа регистрации. Для single tenant укажите Directory (tenant) ID.
8. Выполните `./authorize.command`. Терминал покажет адрес Microsoft и временный код. Откройте адрес в браузере, введите код, войдите в нужный Outlook и разрешите доступ.
9. Дождитесь `Outlook подключён.` Client secret не нужен.

OAuth токены сохраняются отдельно от настроек в закрытом `data/msal-cache.json` (права 600). Это тоже секрет: не отправляйте файл в чат и не коммитьте. `.env` хранит статические ключи; обновляемый MSAL-кэш нужен для refresh token. При отзыве разрешения повторите авторизацию. Если регистрация приложения запрещена, потребуется помощь администратора вашей организации.

Документация: https://learn.microsoft.com/en-us/entra/msal/python/getting-started/acquiring-tokens и https://learn.microsoft.com/en-us/graph/api/user-post-events?view=graph-rest-1.0.

## 5. Запуск

Заполните Telegram-поля `.env` локально в редакторе (например `nano .env`), затем:

```bash
./chatgpt-login.command
./authorize.command  # только для календаря; для общения этот шаг можно отложить
./start.command
```

На macOS можно запускать `start.command` двойным щелчком. Остановить: Ctrl+C в терминале. Закрытие терминала/сон Mac прерывает работу. Запускайте только один экземпляр на один Telegram-токен.

В Telegram: `/start`, `/status`, затем «Привет». `/reset` удаляет историю и ожидающие подтверждения.

`/menu` показывает постоянные кнопки: «Сегодня», «Завтра», «Ближайшие 7 дней», «Добавить событие», «Подключения» и «Лимиты». Просмотр событий кнопками (или командами `/today`, `/tomorrow`, `/week`) выполняется напрямую через Outlook и не расходует запросы ChatGPT. «Добавить событие» показывает пример запроса. «Лимиты» открывает настройки использования ChatGPT; точный остаток подписки бот не получает.

Markdown в ответах преобразуется в нативное оформление Telegram: жирный и курсивный текст, зачёркивание, ссылки, заголовки, списки, цитаты и код. Длинные ответы делятся на сообщения с сохранением выделений и корректным учётом эмодзи. Названия событий и сообщения об ошибках отправляются как обычный текст.

Примеры:
- «Добавь завтра с 15:00 до 16:00 встречу с Антоном, напомни за 15 минут».
- «Что у меня сегодня? А завтра?»
- «Перенеси встречу с Антоном завтра с 16:00 до 17:00» → подтвердите кнопку после проверки.
- «Удали встречу с Антоном завтра» → подтвердите кнопку.

Если время, длительность или событие неоднозначны, бот должен уточнить. Перед подтверждением всегда проверьте показанные название и даты. Для изменений поддерживаются заголовок, начало/конец и напоминание конкретного события; редактирование серий повторений, гостей и отдельных календарей не реализовано. Используется основной календарь. Напоминания приходят средствами Outlook, отправка напоминаний в Telegram не реализована.

В контекст OpenAI передаются последние 20 полных ходов из SQLite, включая результаты календарных инструментов. Более старая история остаётся в базе до `/reset`, но автоматически не подгружается. Ответы модели могут содержать ошибки. Содержимое календаря передаётся OpenAI для обработки запроса.

При сбое сети во время записи сначала проверьте Outlook: сервер мог принять операцию. POST использует transactionId, но повторный пользовательский запрос создаёт новую операцию. Незавершённое подтверждение при сбое не повторяется автоматически. `/status` проверяет наличие OAuth-токена, а не все сетевые сервисы.

## Стиль общения

Личные инструкции владельца можно сохранить в `persona.txt` в каталоге DATA_DIR
(по умолчанию `data/persona.txt`). Они загружаются при запуске и передаются
модели в каждом запросе, в том числе после голосового распознавания.
`/reset` очищает историю, но сохраняет этот профиль. После изменения файла
перезапустите службу. Храните файл с правами 600; каталог data исключён из Git.

## Работа с Gmail и уведомления с кодами

В диалоге доступны поиск и чтение писем, отметка прочитанного, архивирование
и назначение пользовательского ярлыка (отсутствующий создаётся). Для сортировки
нужен запрос владельца, постоянные правила не создаются. Перемещение конкретного
письма в корзину требует кнопки подтверждения на 10 минут. Безвозвратного
удаления и отправки писем нет. Почтовые операции не затрагивают заметки.

Для заметок доступны поиск по словам и чтение текста: «Что у меня в заметках
про фильмы?». Поиск Gmail не является смысловым: при необходимости бот пробует
разные слова или просматривает список заметок. Результаты поиска выдаются по
10 записей с токеном продолжения. Чтение ограничено 20000 символами и сообщает
об обрезке; вложения не скачиваются. Чтение не меняет флаг прочитанности.
Содержимое запрошенных писем/заметок передаётся модели и сохраняется в истории
бота как результат инструмента. Инструкции внутри писем считаются данными.

При подключённом Gmail отдельная фоновая задача примерно раз в 5 секунд
проверяет `history.list` на новые письма. При первом запуске запоминает текущую
точку истории, не пересылая старую почту. Обнаруженный свежий одноразовый код
входа или подтверждения отправляется только TELEGRAM_USER_ID в личный чат:
название отправителя с доменом и код. Используется локальный разбор русских
и английских шаблонов, без модели; письмо не помечается прочитанным.
Спам, корзина, отправленные, черновики, заметки и письма старше 15 минут
пропускаются. Название сервиса берётся из From, это не проверка подлинности
отправителя. Форматы кодов распознаются не все; неоднозначные пропускаются.

`/codes` показывает включённость и время последней успешной проверки,
`/codes off` выключает, `/codes on` включает с новой точкой отсчёта.
Состояние и идентификаторы обработанных писем хранятся в SQLite отдельно
от истории и переживают `/reset` и перезапуск. Сами коды и тела автоматических
уведомлений в базу/журнал не записываются и модели не передаются. Telegram
получает код; сообщения отправляются с protect_content. При неопределённом
результате отправки автоматический повтор подавляется, чтобы избежать дублей.
При истёкшем курсоре истории начинается отслеживание новых писем без догоняющей
рассылки. Это удобство, а не гарантия доставки каждого кода: почта остаётся
источником для проверки. Фоновая проверка использует Gmail API, без запросов
к подписке ChatGPT, публичных портов, Pub/Sub и новых облачных сервисов.

## Справка о возможностях бота

`assistant/capabilities.md` содержит проверенный перечень функций и ограничений.
Agent загружает его при запуске и передаёт модели при каждом запросе, независимо
от истории и `/reset`. Наличие инструмента заметок уточняется по текущему
подключению Gmail. Это помогает не выдавать планы разработки за готовые функции.

Копия справки публикуется в Gmail / Notes под названием
«Что умеет мой Telegram-бот». Она нужна владельцу для просмотра на iPhone.
Бот не читает её автоматически из Gmail; ручные правки этой заметки не меняют
постоянные инструкции. По явному запросу прочитать её теперь можно.
При добавлении функций обновляйте файл, перезапускайте службу и обновляйте копию
в Notes. Идентификатор копии и хеш содержимого хранятся приватно в
`data/bot-capabilities-note.json` на VPS; неопределённый результат публикации
нужно проверить перед повтором, чтобы не создавать дубликат.

## Голосовые сообщения

Пришлите личное голосовое до 60 секунд и 5 МБ. Бот распознаёт его локально
на VPS и сразу обрабатывает как обычный текстовый запрос: общение, календарь
или веб-поиск. Расшифровка в блоке «Распознано» и ответ приходят одним сообщением
(очень длинные ответы разделяются по лимиту Telegram). Отдельной кнопки запуска
голосового запроса нет. Создание события выполняется сразу; перенос и удаление
сохраняют календарное подтверждение. Маленькая модель может ошибаться в датах,
времени и именах: проверьте расшифровку в ответе.

Распознавание: многоязычная Whisper tiny через Faster Whisper, CPU/int8,
один поток и одна запись за раз. Для каждой записи запускается отдельный
процесс: после завершения память модели освобождается. Ожидание распознавания
ограничено 90 секундами. Пока идёт обработка, следующие сообщения ожидают очереди.
Временное аудио удаляется после обработки, ошибки или тайм-аута; исходное
сообщение в Telegram сохраняется. Расшифровка остаётся в сообщении Telegram
и передаётся модели диалога как текст; обработанный ход сохраняется в SQLite.

Установите `requirements-voice.txt` в отдельное Python 3.12 окружение, скачайте
модель `Systran/faster-whisper-tiny` заранее и задайте в `.env`:

```dotenv
VOICE_PYTHON=/absolute/path/to/voice-venv/bin/python
VOICE_MODEL=/absolute/path/to/model-snapshot
```

Каталог модели должен содержать `model.bin`, `config.json` и файлы токенизатора.
Окружение и модель должны быть доступны пользователю systemd-службы на чтение.
Во время распознавания загрузка модели из сети отключена. Без этих настроек
бот продолжает работать с текстом. Аудио не отправляется облачным распознавателям.

## Веб-поиск

В диалог добавлен встроенный инструмент OpenAI `web_search` через существующую
OAuth-авторизацию ChatGPT. Отдельный API-ключ или поисковая подписка не нужны;
доступ зависит от модели и правил аккаунта. Платного резервного режима нет.

Можно написать или сказать «Найди свежие новости Tesla Model Y» или
«Какая завтра погода в Минске?». Инструкции требуют проверять поиском меняющиеся
факты и добавлять источники. Ссылки из аннотаций поиска преобразуются в кликабельные
ссылки Telegram. Модель решает, когда вызвать инструмент, поэтому наличие ссылки
и свежесть источника всё равно полезно проверять. При недоступности поиска бот
должен сообщить об этом и не придумывать актуальные данные.

Вопросы, для которых используется поиск, обрабатываются внешним поисковым
инструментом OpenAI. Содержимое найденных страниц считается данными, а не
инструкциями. Календарные операции доступны в том же диалоге.

Документация: [ограничения ChatGPT plan usage](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

## Проверка

```bash
.venv/bin/python -m compileall -q assistant tests
.venv/bin/python -m unittest discover -s tests -v
```

Локальные тесты не используют реальные секреты и не изменяют ваш календарь. Для живой проверки выполните сценарий выше с тестовым событием и удалите его через подтверждение.

## Перенос на Linux/VPS

Скопируйте код, `.env` и при необходимости `data/` по защищённому каналу. Либо авторизуйтесь заново на сервере через device flow. Используйте Python 3.11+, постоянный локальный диск, права каталога data 700, файлов 600. Для истории делайте SQLite backup через SQLite backup API или копируйте data при остановленном боте; не копируйте только основной .sqlite3-файл при работающем WAL.

Создайте пользователя службы и каталог `/opt/telegram-assistant`, установите зависимости из lock-файла. Пример systemd в `deploy/telegram-assistant.service`: адаптируйте User и WorkingDirectory, установите unit в `/etc/systemd/system`, затем `sudo systemctl enable --now telegram-assistant`. Перед запуском сервера остановите локальный экземпляр. Публичные порты и HTTPS-сертификат не нужны. Не запускайте несколько реплик с одним токеном и общей SQLite.

Логи идут в терминал/systemd journal; содержимое сообщений и ключи намеренно не логируются. Низкоуровневые HTTP-логи отключены, поскольку URL Telegram содержит токен.

Для проверки реальных подключений без изменений календаря: `./check.command`. Диагностика проверяет Telegram getMe, выполняет небольшой запрос из лимита подписки ChatGPT и читает основной календарь Outlook. Она не запускает polling. Ошибки выводятся без секретов.

## Открытый исходный код

Код распространяется по лицензии MIT (см. LICENSE). Публикация исходников не открывает доступ к вашему Telegram-боту, аккаунту ChatGPT или календарю: каждый пользователь настраивает собственные подключения.

Публикуйте только код, тесты, документацию, requirements-файлы, скрипты запуска, deploy/, LICENSE и пустой шаблон .env.example. Не добавляйте .env, .venv/, data/, историю SQLite, OAuth-сеансы, SSH-ключи и логи. Они исключены через .gitignore; это не заменяет проверку списка файлов перед публикацией. Если DATA_DIR вынесен из data/, не размещайте этот каталог внутри публичного репозитория.

Перед первой публикацией создайте отдельный Git-репозиторий непосредственно в папке проекта и проверьте `git status --short` и `git diff --cached --stat`. Не публикуйте родительский домашний каталог.

### Подписка при переносе на сервер

Не переносите chatgpt-host.json с Mac поверх идентификатора сервера: каждой установке нужен собственный host ID. Для открытых проектов OpenAI описывает self-hosted VM и защищённый перенос OAuth-сеанса: https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms. Инструкция переноса относится к приложениям с открытым исходным кодом. Для закрытых удалённо размещённых приложений доступ зависит от условий программы: https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt. Перед переносом перепроверьте доступность этого режима. Переданный сеанс должен обновлять только один экземпляр. Сам по себе пример systemd не гарантирует право использовать подписку на облачном сервере.
