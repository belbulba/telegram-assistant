## Получить код

```bash
git clone https://github.com/belbulba/telegram-assistant.git
cd telegram-assistant
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
.venv/bin/python -m unittest discover -s tests -v
```

Нужен Python 3.11+. Проверенные окружения: Python 3.13 на macOS Intel и
Python 3.12 на Ubuntu 24.04 x86_64. `.venv` создаётся заново на каждом компьютере.
Локальные тесты не требуют настоящих токенов и не обращаются к календарю.

Для разработки и тестов не нужно переносить рабочие секреты или запускать polling.
Рабочий сервер продолжает отвечать независимо от компьютера разработчика.

## Где рабочие настройки и данные

На VPS проект находится в `/opt/telegram-assistant`, служба называется
`telegram-assistant`, запускается от отдельного пользователя с тем же именем.

На сервере, вне Git:

- `.env` — Telegram token, ID владельца, Microsoft Client ID и другие настройки.
- `data/chatgpt-session.json` — действующая OAuth-сессия ChatGPT.
- `data/chatgpt-host.json` — собственный идентификатор установки VPS.
- `data/msal-cache.json` — действующая авторизация Outlook.
- `data/assistant.sqlite3` и возможные WAL/SHM-файлы — история и подтверждения.
- `data/persona.txt` — личный профиль общения; файл нужен для сохранения стиля.

Распознавание использует отдельные окружение и модель вне каталога проекта.
VOICE_PYTHON и VOICE_MODEL в серверной .env указывают на них. Не удаляйте этот
каталог как временный тестовый артефакт: он используется работающим ботом.
При переносе установите requirements-voice.txt в новое окружение, восстановите
модель и обновите оба пути. Точные пути текущего VPS — в DEPLOYMENT.local.md.

GitHub содержит только код и пустой `.env.example`. Клонирование не восстанавливает
рабочую авторизацию и историю. Локальные сессии на старом Mac после переноса могут
быть устаревшими: источником актуального состояния является VPS.

Адрес сервера и сведения о личной регистрации Microsoft записаны отдельно в
`DEPLOYMENT.local.md` на исходном Mac. Этот файл намеренно не попадает в Git.
Для продолжения с нового компьютера перенесите его приватно либо найдите сервер
в панели DigitalOcean. Получите SSH-доступ своим ключом; приватный ключ не
публикуйте. Проще добавить публичный ключ нового компьютера через уже доступный
SSH-сеанс или консоль DigitalOcean.

## Обновить работающего бота

Сначала внесите изменения, выполните тесты, проверьте diff и опубликуйте коммит.
После подключения к VPS выполните:

```bash
cd /opt/telegram-assistant
git pull --ff-only origin main
.venv/bin/python -m pip install --only-binary=:all: -r requirements.lock.txt
.venv/bin/python -m unittest discover -s tests -v
```

Если установка и тесты завершились успешно:

```bash
systemctl restart telegram-assistant
systemctl is-active telegram-assistant
journalctl -u telegram-assistant -n 30 --no-pager
```

Команды службы требуют root или sudo. Дождитесь `Application started` без ошибок.
Проверьте `/menu`, календарную кнопку и обычное сообщение в Telegram.
Не запускайте второй экземпляр с тем же Telegram token.

## Если нужно перенести сам сервер

Сначала остановите старую службу. Код загрузите из GitHub, зависимости установите
заново. Передайте `.env`, SQLite и OAuth-файлы по защищённому каналу. Для нового
хоста ChatGPT создайте отдельный host ID: не копируйте идентификатор старой
установки поверх нового. Следуйте актуальной инструкции OpenAI, указанной в README.

Базу можно копировать при остановленной службе или через SQLite backup API.
Не копируйте только основной файл базы во время работы в режиме WAL.
Права: `data/` — 700, OAuth-файлы — 600. Серверная `.env` сейчас имеет владельца
root, группу telegram-assistant и права 640. После редактирования через dotenv
проверьте владельца и права: замена файла может их изменить.

Перед повторным входом ChatGPT остановите службу. Обновлять одну OAuth-сессию
должен один работающий экземпляр. Вход Outlook запускайте от пользователя службы:

```bash
cd /opt/telegram-assistant
runuser -u telegram-assistant -- .venv/bin/python -u -m assistant.auth
```

После успешной авторизации перезапустите службу. Пароли вводятся только на сайтах
Microsoft/OpenAI. Client secret для текущего Outlook device flow не нужен.

## Карта кода

| Файл | Назначение |
| --- | --- |
| `assistant/main.py` | Telegram, обработчики, доступ владельца, меню, подтверждения |
| `assistant/agent.py` | Диалог и вызовы календарных инструментов через модель |
| `assistant/chatgpt.py` | OAuth ChatGPT, выбор модели, streaming Responses |
| `assistant/auth.py` | Авторизация Microsoft и MSAL-кэш |
| `assistant/calendar.py` | Microsoft Graph, события основного календаря |
| `assistant/menu.py` | Клавиатура и прямой просмотр календаря |
| `assistant/formatting.py` | Markdown → текст и Telegram entities, деление ответов |
| `assistant/store.py` | SQLite, история, одноразовые подтверждения |
| `assistant/voice.py`, `assistant/voice_worker.py` | Последовательное локальное распознавание и ответ с расшифровкой |
| `assistant/web.py` | Преобразование источников веб-поиска в ссылки Telegram |
| `assistant/check.py` | Живая диагностика подключений без записи в календарь |
| `deploy/telegram-assistant.service` | systemd-служба |
| `tests/` | Локальные тесты без секретов |

## Что пока не реализовано

- Telegram-напоминания: напоминания сейчас приходят средствами Outlook.
- Обработка изображений и файлов в Telegram.
- Выбор нескольких календарей, гости и полноценное редактирование повторяющихся серий.
- Пошаговая форма создания события: кнопка добавления показывает пример запроса.
- Точный остаток подписки: кнопка ведёт в настройки ChatGPT.
- Автоматические резервные копии и внешний мониторинг: в сегодняшнюю работу не входили.

Веб-история ChatGPT, память и установленные там плагины не передаются боту.
История бота хранится отдельно; в модель подаются последние 20 ходов.
Создание выполняется по запросу сразу; изменение и удаление требуют кнопки
подтверждения на 10 минут. Сохраняйте это поведение при дальнейших правках.
